# Фабрика челленджей

Платформа 30-дневных челленджей в Telegram: бот, Mini App, API и админка. Первый челлендж «30 дней без сахара» (30 заданий) уже заведён, остальные 18 идей лежат в админке черновиками.

## Что внутри

```
apps/server   API (Fastify) + бот (grammY) + планировщик уведомлений + Prisma/PostgreSQL
apps/miniapp  Mini App участника (React + Vite), открывается по /app/
apps/admin    Админка (React + Vite), открывается по /admin/
```

Один процесс сервера отдаёт API, Mini App, админку и принимает вебхуки Tribute.

**Путь участника.** Реклама → бот `/start` → «УЧАСТВОВАТЬ» → цена и кнопка оплаты Tribute → вебхук об оплате → бот пишет «Оплата получена. Ты в челлендже. Старт: 20 октября. До старта: …» с кнопкой «ОТКРЫТЬ ПРИЛОЖЕНИЕ» → регистрация (ник, возраст, страна, цель) → каждое утро задание → «Я выполнил» → фото/текст или «Пропустить» (или «Я нарушил») → серия, баллы, рейтинг, награды → финальный экран, сертификат с QR, «Поделиться».

**Механика.**
- +10 за выполнение, +5 за доказательство, −10 за нарушение (настраивается в челлендже, баллы дня можно переопределить).
- Бонусы за серию: 3 дня +10, 7 +25, 14 +50, 21 +75, 30 +150. Каждый порог даётся один раз.
- Нарушение или пропуск обнуляет серию, выполненные дни остаются, челлендж продолжается.
- «Спасти серию» за 50 баллов, 1 раз за челлендж, только сразу после срыва.
- Награды: первый день, 7/14/21 день серии, 30 дней, без единого пропуска, ТОП-10.
- Всё пересчитывается из отчётов, поэтому отклонение доказательства в админке сразу меняет рейтинг.
- Чек-лист задания (для «30 дней — не сливаюсь» с 5 пунктами): «Я выполнил» доступно, только когда отмечены все пункты.
- Утреннее задание (по умолчанию 8:00), вечернее напоминание (22:00, «до закрытия дня осталось 2 ч»), «вчера отчёт не был отправлен» — всё по часовому поясу участника, который Mini App присылает автоматически.

**Челленджи и потоки.** Челлендж — это шаблон: 30 заданий, правила, цена, настройки Tribute. Поток — запуск с датой старта. Оплативший попадает в ближайший будущий поток с открытой записью (или в идущий, если будущего нет). Рейтинг считается внутри потока.

## Оплата через Tribute

Подключено к вебхукам Tribute ([документация](https://wiki.tribute.tg/for-content-creators/api-documentation/webhooks)): `new_subscription`, `renewed_subscription`, `cancelled_subscription`, `new_digital_product`. Подпись `trbt-signature` (HMAC-SHA256 тела API-ключом) проверяется, повтор вебхука не задваивает доступ.

Настройка:
1. В Tribute создай подписку 490 ₽ в месяц (подписка в Tribute привязывается к каналу или чату — удобно сделать им чат участников).
2. В Tribute → Настройки → API возьми API-ключ, положи в `TRIBUTE_API_KEY`, а адрес вебхука укажи `https://<твой-домен>/webhooks/tribute`.
3. В админке → челлендж → Настройки → «Оплата (Tribute)»: тип «Подписка», ссылка на оплату и `subscription_id`. Узнать `subscription_id` проще всего так: оплати сам, потом открой «Платежи» в админке, там будет событие «не привязан» с его ID.

Как работает автосписание: первая оплата записывает в поток. Ежемесячное продление (`renewed_subscription`) записывает в следующий поток, если текущий уже закончился. Если следующего потока ещё нет, бот предупреждает, а после создания потока админ нажимает «Записать оплативших без потока». Отмена подписки отключает только автопродление, текущий поток доступен до конца.

Если нужна разовая оплата без автосписания, выбери тип «Разовая покупка» и укажи `product_id` цифрового товара Tribute.

## Запуск локально

Нужны Node.js 22 и PostgreSQL.

```bash
npm install
cp apps/server/.env.example apps/server/.env    # заполни DATABASE_URL, BOT_TOKEN, ADMIN_PASSWORD...
npm run db:migrate                               # создаст таблицы
npm run db:seed                                  # «30 дней без сахара» + черновики
npm run build && npm start                       # http://localhost:3000/app/ и /admin/
```

Для разработки с горячей перезагрузкой: `npm run dev` (сервер), `npm run dev:miniapp`, `npm run dev:admin`. Чтобы открыть Mini App в обычном браузере, поставь `DEV_AUTH=1` и открой `/app/?dev=<любой telegram id>`.

Тесты: `npm test` (подсчёт очков и серий; сквозной сценарий «оплата → отчёт → рейтинг» запускается, если задан `DATABASE_URL`).

## Деплой

Нужен сервер с HTTPS (Telegram открывает Mini App только по HTTPS). Самый простой путь — VPS + Docker:

```bash
cp apps/server/.env.example apps/server/.env   # заполни
docker compose up -d --build
docker compose exec app npx tsx prisma/seed.ts  # один раз
```

Перед ним нужен любой прокси с HTTPS (Caddy, nginx + certbot) на порт 3000. Кнопку меню с Mini App бот ставит сам при старте.

## Переменные окружения

Все описаны в `apps/server/.env.example`. Секреты (`BOT_TOKEN`, `TRIBUTE_API_KEY`, `ADMIN_PASSWORD`) кладутся только в `.env` на сервере или в настройки хостинга, в репозиторий и в чаты их не отправлять.

## Админка

- **Статистика**: пользователи, участия, оплаты, потоки с долей отчитавшихся сегодня.
- **Челленджи**: список, создание (название → 30 дней создаются по шаблону), настройки, 30 заданий (заголовок, описание, задание, подсказка, изображение, баллы, нужно ли фото, чек-лист), потоки.
- **Участники**: Telegram ID, имя, username, регистрация, оплата, день, серия, баллы, место, статус; поиск, CSV, ручное добавление в поток, отключение.
- **Результаты**: лента отчётов с фото и текстом, отклонение доказательства.
- **Рассылка**: всем, участникам челленджа или потока, с кнопкой «открыть приложение».
- **Платежи**: журнал вебхуков Tribute.

## Что не вошло в MVP

- Фото хранятся на диске сервера (`UPLOADS_DIR`). Для нескольких серверов понадобится S3-хранилище.
- «Спасти серию» за деньги, пакеты и клуб 990 ₽/мес: модель данных к ним готова (несколько челленджей, подписки), но экраны продаж не сделаны.
- Модерация доказательств ручная.
